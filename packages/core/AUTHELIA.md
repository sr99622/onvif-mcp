# Camera System Authelia Transition Runbook

## Purpose

This document records the transition of the camera web application and proxied MediaMTX WebRTC streams from Nginx HTTP Basic Authentication to an Authelia form-login session.

The final design eliminates the browser-native Basic Authentication dialog that interfered with Chrome automation, while preserving Basic Authentication on the Camera MCP endpoint for OpenClaw.

## Final architecture

### Public HTTPS endpoints

| Endpoint | Authentication | Backend |
|---|---|---|
| `https://camera.home.arpa/cameras/` | Authelia session | Static files served by Nginx |
| `https://camera.home.arpa/multiview/` | Authelia session | Static files served by Nginx |
| `https://camera.home.arpa/outputs/` | Authelia session | Static files served by Nginx |
| `https://camera.home.arpa/webrtc/` | Authelia session | MediaMTX at `127.0.0.1:8889` |
| `https://camera.home.arpa/authelia/` | Public login portal | Authelia at `127.0.0.1:9091` |
| `https://camera.home.arpa/mcp` | Nginx Basic Auth | Camera MCP at `127.0.0.1:8001` |

Authelia and both application backends listen only on loopback. Nginx is the sole HTTPS entry point.

### Authentication flow

1. A browser requests a protected camera URL.
2. Nginx makes an internal authorization subrequest to Authelia.
3. If no valid session cookie exists, Authelia returns a login redirect.
4. The browser displays the Authelia form at `/authelia/`.
5. After successful login, Authelia sets a cookie scoped to `camera.home.arpa`.
6. The browser returns to the original camera URL.
7. Subsequent camera page and WebRTC requests use the session cookie without a browser-native credential popup.

The MCP endpoint deliberately remains separate. OpenClaw supplies its existing Basic `Authorization` header, and Nginx removes that header before proxying the request to the MCP application.

## 6. Why the portal uses a path instead of `auth.home.arpa`

The initial design used a separate portal hostname:

```text
auth.home.arpa
```

A DNS record and CA-signed certificate were created for it. Validation then failed with:

```text
session: domain config #1 (domain 'home.arpa'): option 'domain' is not a valid cookie domain: the domain is part of the special public suffix list
```

Authelia would need to place a shared session cookie on `home.arpa` for both `auth.home.arpa` and `camera.home.arpa`. Browsers and Authelia prohibit this because `home.arpa` is a special-use public suffix.

The selected solution was to host the portal beneath the protected hostname:

```text
https://camera.home.arpa/authelia/
```

The session cookie can then be scoped to `camera.home.arpa`, and the existing `camera.home.arpa` certificate secures the portal. Authelia itself communicates with Nginx over loopback HTTP, which never leaves trigkey.

The unused `auth.home.arpa` DNS record and trigkey certificate files were removed. The CA workspace retains issuance serial `0x1001` and related records for audit history. Its unused private key was removed from active storage on trigkey.

## 8. Nginx Authelia snippets

The Ubuntu Nginx build includes the required module:

```text
--with-http_auth_request_module
```

### Internal authorization endpoint

File:

```text
/etc/nginx/snippets/authelia-location.conf
```

Contents:

```nginx
set $upstream_authelia http://127.0.0.1:9091/api/authz/auth-request;

location = /internal/authelia/authz {
    internal;
    proxy_pass $upstream_authelia;

    proxy_set_header X-Original-Method $request_method;
    proxy_set_header X-Original-URL $scheme://$host$request_uri;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header Content-Length "";
    proxy_set_header Connection "";

    proxy_pass_request_body off;
    proxy_http_version 1.1;
    proxy_buffers 4 32k;
    proxy_read_timeout 240s;
    proxy_send_timeout 240s;
    proxy_connect_timeout 240s;
}
```

The `internal` directive prevents clients from accessing this endpoint directly.

### Per-location authorization

File:

```text
/etc/nginx/snippets/authelia-authrequest.conf
```

Contents:

```nginx
auth_request /internal/authelia/authz;

auth_request_set $user $upstream_http_remote_user;
auth_request_set $groups $upstream_http_remote_groups;
auth_request_set $name $upstream_http_remote_name;
auth_request_set $email $upstream_http_remote_email;

proxy_set_header Remote-User $user;
proxy_set_header Remote-Groups $groups;
proxy_set_header Remote-Name $name;
proxy_set_header Remote-Email $email;

auth_request_set $redirection_url $upstream_http_location;
error_page 401 =302 $redirection_url;
```

## 9. Nginx HTTPS server integration

The active site file is:

```text
/etc/nginx/sites-available/camera-apps
```

A pre-change backup was made at:

```text
/etc/nginx/sites-available/camera-apps.before-authelia-2026-08-05
```

The server-wide Basic Auth directives were removed. The following server-level include was added:

```nginx
include /etc/nginx/snippets/authelia-location.conf;
```

### Authelia portal proxy

```nginx
location = /authelia {
    return 301 /authelia/;
}

location /authelia/ {
    proxy_pass http://127.0.0.1:9091;
    proxy_http_version 1.1;

    proxy_set_header Host $host;
    proxy_set_header X-Original-URL $scheme://$host$request_uri;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-Host $host;
    proxy_set_header X-Forwarded-URI $request_uri;
    proxy_set_header X-Forwarded-Ssl on;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Real-IP $remote_addr;

    proxy_set_header Connection "";
    proxy_buffering off;
}
```

This location must not include the Authelia authorization snippet; otherwise the login portal would protect itself and create a redirect loop.

### Protected static paths

Each browser-facing static location includes:

```nginx
include /etc/nginx/snippets/authelia-authrequest.conf;
```

Example:

```nginx
location /cameras/ {
    include /etc/nginx/snippets/authelia-authrequest.conf;
    try_files $uri $uri/ =404;
}
```

The same applies to `/multiview/` and `/outputs/`.

### Protected WebRTC proxy

```nginx
location /webrtc/ {
    include /etc/nginx/snippets/authelia-authrequest.conf;
    proxy_pass http://127.0.0.1:8889/;
    proxy_redirect / /webrtc/;
    proxy_set_header Authorization "";
}
```

### Protected catch-all

This prevents direct requests to `/`, `/index.html`, or other files from bypassing authentication:

```nginx
location / {
    include /etc/nginx/snippets/authelia-authrequest.conf;
    try_files $uri $uri/ =404;
}
```

### MCP remains on Basic Authentication

Basic Auth was moved from server scope into the exact MCP location:

```nginx
location = /mcp {
    auth_basic "Camera System";
    auth_basic_user_file /etc/nginx/auth/camera-users.htpasswd;

    proxy_pass http://127.0.0.1:8001;
    proxy_http_version 1.1;

    proxy_set_header Authorization "";
    proxy_set_header Connection "";

    proxy_buffering off;
    proxy_request_buffering off;
    proxy_cache off;

    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
}
```

This preserves the OpenClaw configuration while preventing MCP credentials from reaching the application backend.

### Validate and reload Nginx

```bash
sudo nginx -t
sudo systemctl reload nginx.service
```

Never reload if `nginx -t` reports an error.

## 12. Recovery outline

Do not extract the archive directly over a running installation without first reviewing its contents.

1. Install `age`, Authelia, and Nginx on the recovery host.
2. Decrypt into a temporary directory:

   ```bash
   install -d -m 700 /tmp/camera-auth-restore
   age -d camera-auth-stack-2026-08-05.tar.gz.age |
     tar -xzf - -C /tmp/camera-auth-restore
   ```

3. Inspect all paths and permissions in the temporary directory.
4. Stop Authelia before restoring its SQLite database and secrets.
5. Restore files to their original absolute locations.
6. Confirm ownership:
   - Authelia configuration, secrets, and data: `authelia:authelia`
   - Nginx files: normally `root:root`, with the htpasswd file `root:www-data`
7. Run the Authelia configuration validator with secret-file environment variables.
8. Run `sudo nginx -t`.
9. Start Authelia and reload Nginx.
10. Repeat the curl, browser, and OpenClaw tests in this document.

Use a dedicated temporary directory rather than extracting into `/`, and remove it securely after successful recovery.

## 14. Lessons learned

### Do not leave dnsmasq backups in `/etc/dnsmasq.d`

This installation starts dnsmasq with:

```text
-7 /etc/dnsmasq.d,.dpkg-dist,.dpkg-old,.dpkg-new
```

Only the listed suffixes are excluded. A `.bak` file is still parsed. An earlier backup left inside `/etc/dnsmasq.d` caused dnsmasq to fail with an `illegal repeated keyword` error.

Store dnsmasq backups outside `/etc/dnsmasq.d`, not merely with a `.bak` suffix.

### Validate cookie domains before issuing certificates

Authelia rejected `home.arpa` as a cookie domain because it is a special public suffix. Validate the proposed session-cookie topology before creating DNS records and certificates for a separate authentication hostname.

### Keep machine clients separate from browser sessions

Authelia form login is well suited to human browser sessions. The MCP client already had a reliable Basic Auth header and private-CA trust configuration, so `/mcp` retained Basic Auth. This avoids forcing an interactive browser flow onto a machine client.

### Keep backends on loopback

Authelia, MediaMTX WebRTC HTTP, and Camera MCP are not exposed directly to the LAN. Nginx is responsible for TLS and access control. This substantially reduces the number of externally reachable services.
