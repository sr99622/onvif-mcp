# Password Store (`pass` + GPG) Setup Record & Runbook

## Purpose

Document the local, offline password manager used to hold the passphrases created during
private CA generation (`CREATE_CA_CERT.md`) so they are recoverable without relying on an
agent transcript.

No cloud service or account is involved. Everything is GPG-encrypted locally; encrypted
copies live on the SMB share at `/mnt/taurus/Camera-CA-Backups/`.

This document is a record of what was actually done on `nuc` (2026-09-01) and doubles as
the runbook for doing it again. Supersedes the 2026-08-31 draft recorded on `intel`.

## Environment (verified 2026-09-01)

- Host: `nuc`, Ubuntu 26.04.1 LTS, user `stephen`
- `sudo` works non-interactively (unlike the old `intel` box); OpenSSL 3.5.5; age 1.2.1
- No password manager preinstalled; no GPG key present (`~/.gnupg` did not exist)

## Hard rules

1. **The agent never generates the GPG key.** The user runs `gpg --full-gen-key` in their
   own real terminal and sets its passphrase there. The key's passphrase is the one
   remaining secret — it must never pass through an agent session, command line, or file.
2. Secrets are generated by the agent with a CSPRNG (`openssl rand`), written into `pass`
   via stdin, and every intermediate copy is wiped with `shred -u`. They are never printed.
3. The encrypted key on SMB shares and the vault entries are verified by their consumers
   (openssl / age), never by reading them back.

## 1. Install `pass`

Straight apt (root available on this host):

```bash
sudo apt install pass
pass --version        # pass v1.7.4
```

(The `intel` box had no usable sudo TTY, hence the old download-and-extract procedure —
not needed here.)

## 2. GPG key (created by the USER, not the agent)

The agent must **ask the user** to create the key in their own terminal; it may not run
key generation itself. Previously an agent-generated batch key with a throwaway
passphrase was used as a placeholder — that forced a user passphrase reset and should not
be repeated.

User, in their own real terminal:

```bash
gpg --full-gen-key
```

Choose an ed25519 signing key (the subkey type `ed25519` + encryption subkey cv25519 is
the recommended default). Note the user ID and fingerprint.

The agent then verifies it exists without ever handling the passphrase:

```bash
gpg --list-keys <user-id>   # expect pub ed25519 [SC] + sub cv25519 [E]
```

This machine's key (2026-09-01): `Stephen Rhodes (Temp keystore) <sr99622@gmail.com>`,
fingerprint `E47D2BCAF7D631EC246E2829EFF6AB1D9D314616` — ed25519 `[SC]` + cv25519 `[E]`.

The user is responsible for exporting the secret key as a backup (section 7). The agent
must not run that export either: it prompts for the user's passphrase.

## 3. Initialize the store

Bare `pass init` fails with a usage error (key not auto-detected); an explicit key ID is
required on this box:

```bash
pass init <user-id>        # e.g. pass init sr99622@gmail.com
cat ~/.password-store/.gpg-id
```

## 4. Generate and store the CA passphrases

Generate two independent random values (each into a 0700 temp file, never echoed):

```bash
umask 077
openssl rand -base64 24 | tr -d '=+/' | cut -c1-28 > /tmp/.ca-root-key-pass   # root CA key
openssl rand -base64 24 | tr -d '=+/' | cut -c1-28 > /tmp/.ca-age-archive     # age archives
```

Store them (masked), then wipe the temp files immediately:

```bash
pass insert -m camera-ca/root-key-passphrase < /tmp/.ca-root-key-pass
pass insert -m camera-ca/age-archive-<DATE>    < /tmp/.ca-age-archive
shred -u /tmp/.ca-root-key-pass /tmp/.ca-age-archive
ls -la ~/.password-store/camera-ca/   # per-entry .gpg files, mode 600
```

`pass show camera-ca/<name>` prompts for the GPG passphrase; gpg-agent caches it, so once
the user has typed it a few times (e.g. when they set it in their terminal), later
`pass show` calls work headless within the same session.

## 5. Verified command patterns (this host)

OpenSSL 3.5.5 here will not accept `-passin file:` for encrypted *write* operations
(`openssl genpkey -aes-256-cbc` errors with "Multiple cipher or unknown options"; even
the plain form aborts its UI on non-tty stdin). The working routes, all verified:

**Encrypted key generation (two prompts: passphrase + verify)** — feed both lines into a
PTY via `script`, stdin-fed so it cannot hang:

```bash
bash -lc 'pass show camera-ca/root-key-passphrase; pass show camera-ca/root-key-passphrase' \
  | script -qec "stty -echo 2>/dev/null; \
      openssl genpkey -algorithm RSA -aes-256-cbc -pkeyopt rsa_keygen_bits:4096 \
        -out <CA_DIR>/private/camera-system-root-ca.key.pem" /dev/null
```

**Decryption/verification reads work with plain piped stdin** (no PTY needed):

```bash
pass show camera-ca/root-key-passphrase | \
  openssl pkey -in <CA_DIR>/private/camera-system-root-ca.key.pem -check -noout
# -> Key is valid

pass show camera-ca/root-key-passphrase | \
  openssl req -config <CA_DIR>/openssl.cnf \
    -key <CA_DIR>/private/camera-system-root-ca.key.pem \
    -new -x509 -days 3650 -sha256 -extensions v3_ca \
    -subj "/CN=Camera System Root CA" \
    -out <CA_DIR>/certs/camera-system-root-ca.crt.pem
```

**age reads its passphrase from `/dev/tty`** — a file redirect (`age -p < file`) fails
with "/dev/tty not available". Use the stdin-fed `script` pattern; feed two lines for the
encrypt prompts ("Enter passphrase" + "Confirm passphrase"), one line for `-d`:

```bash
# encrypt (two prompts)
bash -lc 'pass show camera-ca/age-archive-<DATE>; pass show camera-ca/age-archive-<DATE>' \
  | script -qec "stty -echo 2>/dev/null; set -o pipefail; \
      tar -C <CA_ROOT> -czf - camera-system-ca | \
      age -p -o <CA_ROOT>/backups/camera-system-ca-initial-<DATE>.tar.gz.age" /dev/null

# verify decryption (one prompt)
bash -lc 'pass show camera-ca/age-archive-<DATE>' \
  | script -qec "stty -echo 2>/dev/null; age -d <archive> > /tmp/.ca-decrypted.tgz" /dev/null
tar -tzf /tmp/.ca-decrypted.tgz    # must list key, cert, openssl.cnf, index.txt, serial, crlnumber
shred -u /tmp/.ca-decrypted.tgz    # wipe the decrypted copy immediately
```

A one-shot foreground `script` wrapper that runs everything inside hangs (60 s timeout);
always pipe the passphrase lines in from outside as shown.

## 6. Backups (on `/mnt/taurus/Camera-CA-Backups/`)

This pass version stores **per-entry `.gpg` files**, not a single `store.gpg`, so store
backups must include the whole directory including the hidden `.gpg-id`:

```bash
tar -C ~/.password-store -czf \
  <CA_ROOT>/backups/password-store-backup-<DATE>.tar.gz camera-ca .gpg-id
cp --update=none <local archive files> /mnt/taurus/Camera-CA-Backups/
cat ~/.password-store/.gpg-id > /mnt/taurus/Camera-CA-Backups/pass-gpg-id.txt
sha256sum <local> <smb copy>   # hashes must match exactly
```

Final SMB contents after the 2026-09-01 run:

```text
/mnt/taurus/Camera-CA-Backups/
├── camera-system-ca-initial-2026-09-01.tar.gz.age   # full CA state (age, passphrase)
├── password-store-backup-2026-09-01.tar.gz          # vault entries + .gpg-id (GPG-encrypted)
└── pass-gpg-id.txt                                   # the store's .gpg-id value
```

## 7. GPG private key export (USER-run only)

Because the agent never holds the key's passphrase, only the user can export the secret
key. In their own terminal:

```bash
gpg --armor --export-secret-key <user-id> > ~/ca-vault-gpg.key.gpg
chmod 600 ~/ca-vault-gpg.key.gpg
cp ~/ca-vault-gpg.key.gpg /mnt/taurus/Camera-CA-Backups/
sha256sum ~/ca-vault-gpg.key.gpg /mnt/taurus/Camera-CA-Backups/ca-vault-gpg.key.gpg
gpg --list-packets <keyfile>   # must show a v4 passphrase-protected secret key packet
```

Losing `~/.gnupg` and the exported key at the same time is unrecoverable even if all
backup files survive. This step was **still pending** as of 2026-09-01 — do it.

## 8. Recovery procedure (fresh machine)

In order:

1. Import the GPG key (prompts for the user's passphrase):
   ```bash
   gpg --import ca-vault-gpg.key.gpg
   ```
2. Restore the store:
   ```bash
   mkdir -p ~/.password-store
   tar -xzf password-store-backup-<DATE>.tar.gz -C ~/.password-store
   ```
3. Ensure `pass` is installed and check a secret:
   ```bash
   pass show camera-ca/age-archive-<DATE> | wc -c    # 29 bytes (28-char value + newline) -> readable
   ```
4. Decrypt and restore the CA state (section 5 PTY pattern):
   ```bash
   age -d camera-system-ca-initial-<DATE>.tar.gz.age | tar -xz -C <target dir>
   ```

## Pitfalls and notes (learned the hard way, 2026-09-01)

- **Never generate the GPG key yourself.** The one time it was done agent-side with a
  placeholder passphrase, the user hit an "enter pass phrase" prompt for a secret nobody
  in the session knew, and had to reset it. Always ask the user to run `gpg --full-gen-key`
  first; the agent only verifies with `gpg --list-keys`.
- **`pass init` needs an explicit key ID** on this box; bare init failed with a usage error.
- **Per-entry `.gpg` files** in this pass version: back up the whole directory including
  the hidden `.gpg-id`, not one file.
- **OpenSSL encrypted writes reject `-passin file:` and non-tty stdin** on 3.5.5; use the
  two-line `script -qec` PTY pattern. Decryption reads are fine with a plain pipe.
- **age's passphrase is /dev/tty-only**: file redirects fail; use the stdin-fed `script`
  pattern, and keep it outside-in so the one-shot wrapper can't hang.
- Wipe every intermediate secret file with `shred -u` in the same command chain that used
  it; a single stray copy survived a cleanup sweep once and had to be hunted down.
- The key's user ID says "Temp keystore" — created ad hoc for this purpose, but it now
  permanently guards the vault and CA passphrases; treat it as long-lived infrastructure.
